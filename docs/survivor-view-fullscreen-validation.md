# 全螢幕固定面積視野交接

來源：`coord/inbox/done/20261026T130249Z-parent-view-fullscreen.md`。版本：`20261026ao`。

## 行為

- `worldViewport(w,h)` 使用 `zoom = sqrt(w*h/320000)`，可見寬高為 `w/zoom`、`h/zoom`。不取整，偏移固定為 0；世界畫面鋪滿整個 Canvas，移除舊留邊底色與內框裁切。
- 四種指定尺寸都看到 320000 平方世界單位，面積差為 0%，符合 ±25～30% 要求；比例依裝置改變，並非每台看到同樣的長寬。
- 740×360 約顯示 811×395 世界單位，比 #89 之前的 740×360 兩個方向均稍大，面積增加約 20%。1024×768 約為 653×490，1180×820 約為 679×472；平板透過放大達成接近的可見面積。
- 沿用 `imageSmoothingEnabled = false`；非整數縮放可能有像素寬度不均，清晰度仍需實機確認。
- HUD、搖桿及老師箭頭邊距保留 CSS 像素；手動瞄準沿用逆縮放。安全圈、生怪、地圖與老師追擊沿用世界單位，沒有調整戰鬥數值。練習場共用新視野；純效果展示保留自己的鏡頭構圖。

## 驗證

僅執行 `node games/survivor/tools/test.cjs`，未加 `--layout`。最後完整一輪全部通過（exit 0），`git diff --check` 通過。第一輪發現箭頭測試混用世界與螢幕單位，修正案例後重跑完整入口通過。

純函式案例覆蓋 740×360、844×390、1024×768、1180×820：可見面積與容許範圍、零偏移、畫面寬高完整覆蓋、手機最小視野、四角與斜向瞄準還原、關閉像素平滑、固定地圖與安全圈。老師箭頭案例改為實際套用各裝置視野，檢查縮放後保留 30 CSS 像素邊距。

## Grok 實機審查

請審查 erin-watch 提交的實質 SHA，在 **740×360、1024×461、1180×820** 各實際操作：

1. 確認遊戲畫面四邊填滿、沒有黑邊或留邊；比較視野與像素清晰度，檢查 HUD、搖桿大小。
2. 向四個方向及斜角拖曳手動瞄準、攻擊；直拿旋轉後再試，並確認練習場方向正確。
3. 打老師並持續拉開距離，確認老師快走追趕、畫面外箭頭及跳躍／狙擊仍能造成壓力。確認安全圈、生怪與既有招式正常。
