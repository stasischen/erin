# 八種小怪與出怪節奏初版

依據家長收件匣 `coord/inbox/done/20261026T014019Z-parent-enemy-pacing-build.md`：「先這樣做一版 之後再看會不會太密」。這次有實作遊戲，工程初值留待 Grok 審查、Erin 試玩；沒有核准上線。版本 `20261026i`，HTML、展示網址與 Service Worker 快取同步。

## 玩得到的變化

- 小熊軟糖追趕；蒲公英弧線快跑；布丁慢而耐打，擋住其他怪物；蘑菇保持距離、預警後射擊並後退；甜甜圈預告固定方向後衝撞；跳跳糖紅色閃爍兩秒後自爆，傷到主角與其他怪物；果凍死亡分裂兩隻；棉花糖仙子預告後替附近小怪加限時護盾。
- 普通小熊／蒲公英保留原先等級門檻射擊，這次也先預警。所有新增攻擊在畫面內才啟動，離開視野取消準備；衝刺保護仍有效。接觸型碰撞沿用既有規則。
- 普通生成、精英、事件、大熊與老師都從畫面外進場。果凍子體是家長允許的例外，在死亡位置左右 10 遊戲單位出現，不繼續分裂。既有精英「分裂」能力仍為三隻、從畫面外生成，與果凍行為分開。
- 糖果森林固定果凍＋跳跳糖，餅乾森林固定布丁＋甜甜圈；每關抽另外兩種（不重複、不與主題重複），加上全程的軟糖與蒲公英。每三次普通生成至少一次軟糖。
- 0–20 秒只有軟糖，20 秒加蒲公英，45 秒加入本場已抽到的其他種類（坦克與自爆延到 70 秒），70 秒後混合本場六種；100–120 秒沿用更密的最後波次，120 秒老師出場。大熊沿用每關時間一半，預設 60 秒。
- 45／90 秒從「包圍、蒲公英湧潮、精英小隊、跳跳糖群」抽兩個不同事件。先文字／聲音提示，預警結束才依序進場；包圍輪流從四邊來，湧潮從同一側來，留走位時間。事件不取消普通波次，數量滿額則等候；精英達到自己的上限則跳過該隻。

這是把原備忘未定部分接成可玩的工程初版：最後混合的是「本場六種」，事件不固定 45 秒一定包圍；兩種額外怪與兩種事件每關重抽。既有兩分鐘時間軸維持絕對秒數，Maker 若縮短老師出場時間，較晚事件不提前到 Boss 戰。這些初版選擇可以在試玩後再調，不代表 Erin 已確認平衡。

## Maker 與資料

「怪物」頁新增出怪節奏、波次型態（預設強弱交替，可選穩定）、每關每段出怪間隔，以及八種怪物的既有數值／行為控制。`pacing` 在 `data/defaults.js`；數值界線在 `data/schema.js` 的 `PACING_BOUNDS`。預設密度 1，每 10 秒交替 0.7／1.15 密度；每次事件 6 隻、10 秒進場；攻擊預警 0.9 秒；自爆引信固定兩秒、半徑 85、對主角傷害 18／對怪物 90；護盾範圍 150、維持 5 秒、擋 1 下，不疊加。

怪物血量／速度／碰撞傷害／大小沿用既有安全界線；新種類以穩定 id 增補，舊兩種怪物作品保留原本設定。關卡僅開放既有波次的 `every`（0.3–5 秒），時間、id、主題與事件池仍固定。波次型態、強弱倍率、週期及事件數量可儲存。原設定頁仍可調整兩種基礎怪與全局出怪倍率，Maker 試玩則採作品值。

怪物上限仍為 26，精英仍遵守既有上限，果凍佇列最多 18 個，事件最多 10 個。跳跳糖自爆消耗本體，不計玩家擊殺／掉落；被爆炸擊倒的其他怪物仍走共用死亡結算與果凍分裂。護盾有時限，仙子不替自己加盾，離開範圍不立即消失，等到時限或被打破。

布丁、跳跳糖、仙子新增原創 24×24 程式點陣圖，其他造型沿用；共 16 種可選造型。未使用外部素材。

## Godot §11 對照與差距

- §11.1：敵人與節奏放在可序列化 `defaults`，沿用 schema v1 並遷移舊作品；未全面抽成 JSON 檔。單位為秒、遊戲距離、血量／傷害、倍率；可調範圍以 schema 與 Maker 標籤為準。
- §11.2／11.6：本場候選、兩種抽選、分段候選及密度為純函式，亂數樣本由外層傳入。行為與傷害的執行層仍使用既有 state／共用傷害入口，尚非全純函式；新測試固定初始狀態與 dt，可移植同等案例。
- §11.3：果凍死亡由既有 `encounterDefeated` 接入，只排入 `{typeId,x,y}` 資料，下一更新邊界生成，不重複結算；沒有新增事件匯流排。事件佇列同樣只存 kind／index 等資料。
- §11.4／11.5：新增造型保持 24×24、最近鄰縮放，保留程式原稿；尚未匯出 PNG／sprite sheet。沿用既有預警音效，未改音訊或匯出 WAV／OGG。
- §11.7：行為使用世界座標、秒與既有可見性／環形座標工具；規則不查 CSS 或 DOM。預警繪製集中 `render/world.js`，抽選／節奏與行為在 `engine/pacing.js`。可見範圍與平台接合仍沿用既有引擎，未全面重構。
