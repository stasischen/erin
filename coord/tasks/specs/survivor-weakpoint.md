# 共用弱點積木與護甲傷害

任務：`survivor-weakpoint`。由既有 weakpoint.md 整理為可公開規格；本檔與對應 JSON 是正式來源，舊 /tmp 副本不再驅動開工。

實作者與獨立審查員均在 Mac Studio 跑完整 `node games/survivor/tools/test.cjs --layout`；不新增 GitHub CI。一次一張，開 PR 後交獨立 session 審查，合併上線後回報並等家長決定下一步。

## 共用「弱點」積木
- Boss 由部位組成：一般部位有護甲，打到只造成約 15–25% 傷害（Maker 可調），並播放「小」等級的「鏗」回饋（火花＋金屬聲，不用 emoji）。
- 弱點在條件成立時打開，打到造成約 3 倍爆擊並播放「大」等級回饋。
- 開啟條件（可組合）：某招之後／收招時、Boss 背對主角、撞牆暈眩、架勢崩潰、被環境或誘餌引出。
- 弱點打開時有清楚預警：身上發光、閃爍外框；關閉前也有短暫提示。
- 每隻 Boss 的弱點寫在資料裡：位置錨點用美術清單（asset manifest）的錨點、可用角度弧（背後、正面）判斷是否命中、開啟時間。Maker 新增「弱點」積木可調。
- 套用：老師（收招與架勢崩潰時露出弱點）、巨斧守門人（背後是弱點；衝鋒撞牆暈眩時弱點打開）。

## 競技場大小
- 王的試煉競技場約一個固定面積視野大小（視野約 800×400 世界單位），最多 1.2–1.5 倍；鏡頭幾乎看得到整個競技場，Boss 永遠在畫面內或畫面邊緣。
- 使用 survivor-trial-hotfix 之後的共用競技場尺寸與 AI 距離帶，不另外放大。

## 共同規則
- 每一招都有預警（地面範圍、蓄力動作、身上發光），不用文字橫幅；小怪／召喚物只從 Boss 身上冒出，絕不在畫面內憑空出現。
- HUD 圓形、只有像素圖示，不用 emoji；固定橫向、全螢幕；主角蓄力攻擊只朝前方。
- 用 survivor-boss-ai 狀態機與 AI 規則積木、survivor-godot-art-prep 的美術清單；資料驅動、Godot 友善，數值在 Maker 可調。
